git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Above commands set your Git username and email globally.

git init is used to initialize a new Git repository in the current directory.
this .git keeps track of all changes made to files in this directory.

but these won't be tracked until you add them to the staging area using git add <filename_1> <filename_2> ...
or git add . to add all files.

git init itself doesn't track changes until you explicitly tell it to do so. and this is done using git add command.

staging means preparing files to be committed. commit means saving the changes to the local repository.

After staging, you can commit the changes with -> git commit -m "Your commit message"
This saves the changes to the local repository. Here local repository means the .git folder in your project directory.

You can check the status of your files using -> git status
to see which files are staged, unstaged, or untracked.

To view the commit history, use -> git log
This shows a list of all commits made in the repository along with their messages and IDs.

git log --oneline 
git show <commit-id> give details of a specific commit.

-> git diff shows the differences between the (working directory vs the staging area)
shows lines that were added, modified, or deleted in files since the last git add. cmd (i.e., since last staging)

but git diff --staged shows the differences between the staging area and the last commit.

git blame <file_path> shows who made changes to each line of a file and when.

In order to ignore certain files from being tracked by git, you can create a .gitignore file in the root directory of your repository.
In this file, you can list the names or patterns of files and directories that you want Git to ignore.


-> git reset <file_path> unstages a file, moving it from the staging area back to the working directory.
when you run git reset <file_path>, the changes in that file remain in your working directory, but they are no longer staged for the next commit.

-> git reset --hard <commit-id> resets the current branch to the specified commit and discards all changes in the working directory and staging area.

git revert <commit-id> creates a new commit that undoes the changes made in the specified commit.

git rm --cached <file_path> removes a file from the staging area but keeps it in the working directory.

git clone <repository_url> is used to create a copy of an existing remote repository on your local machine.
This command creates a new directory with the same name as the repository and initializes a new Git repository in that directory. It also fetches all the files and commit history from the remote repository.

git remote add origin <repository_url> is used to add a remote repository to your local Git repository. 
This command sets up a connection between your local repository and the remote repository, allowing you to push and pull changes between the two.

Diff btwn git clone and git remote add origin:
git clone is used to create a copy of an existing remote repository on your local machine,
while git remote add origin is used to add a remote repository to an existing local Git repository.
